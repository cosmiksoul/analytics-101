# Учебный журнал событий темы «Продуктовые метрики и события»

Общий набор данных темы 09 курса «Аналитика 101». Тот же интернет-магазин товаров для дома, что в темах 02–08, теперь с приложением (Android, iOS) и сайтом: всё, что делают люди, падает строками в журнал. Данные учебные: их сделал `gen.py` с зерном 909. Журнал понадобится и в теме 11.

Период — 25 полных недель, с понедельника 5 января по воскресенье 28 июня 2026 года. Время в журнале — UTC.

## Файлы

| файл | что внутри |
|---|---|
| `events.parquet` | журнал: 316 518 строк, 15 столбцов. pandas читает его через `read_parquet`, DuckDB — прямо из файла |

## Столбцы журнала

| столбец | что это |
|---|---|
| `event_id` | id события. **Не уникален:** 4 540 клиентских событий (1,5%) пришли дважды с тем же `event_id` |
| `event_time` | время в UTC, например `2026-05-12T16:49:20Z` |
| `event_name` | имя события, см. план событий |
| `origin` | `client` — прислало приложение или сайт; `server` — записал сервер магазина |
| `anonymous_id` | id устройства (`d_…`). У серверных событий пусто |
| `user_id` | id аккаунта (`u_…`). Пусто, пока человек не вошёл на этом устройстве |
| `platform` | `android`, `ios`, `web` |
| `app_version` | версия приложения; у сайта пусто |
| `country` | BY, RU (UTC+3), KZ, UZ (UTC+5) |
| `traffic_source` | только у `app_open`: `search`, `direct`, `ad`, `partner`, `push`, `email` |
| `product_id`, `category`, `price` | у `product_view` и `add_to_cart` |
| `order_id` | у `order_paid` и `purchase` |
| `revenue` | сумма корзины, ₽: у `checkout_start`, `order_paid`, `payment_failed`, `purchase` |

## План событий

| событие | откуда | когда |
|---|---|---|
| `app_open` | клиент | открыл приложение или зашёл на сайт |
| `product_view` | клиент | открыл карточку товара |
| `add_to_cart` | клиент | положил товар в корзину; около 10% сессий начинаются с «быстрого добавления» из каталога, без карточки |
| `sign_up`, `login` | клиент | регистрация, вход; с этого события у устройства есть `user_id` |
| `checkout_start` | клиент | начал оформление |
| `order_paid` | сервер | оплата прошла — источник правды о заказах и выручке |
| `payment_failed` | сервер | оплата не прошла |
| `purchase` | клиент | экран «Спасибо за заказ», через 1–4 секунды после `order_paid` |

## Соглашения темы

Страницы 9.1–9.4 считают по шести правилам; числа ниже посчитаны по ним.

1. Человек — аккаунт: устройству приписывают аккаунт, который на нём входил, во всех строках. Без входа человек — устройство.
2. Без дублей `event_id`.
3. Без ботов: устройство с более чем 100 клиентскими событиями за минские сутки.
4. День — по Минску, UTC+3. Неполные края журнала — вечер 4 января и 29 июня по Минску — отбрасываются.
5. Сессия — 30 минут неактивности на устройстве.
6. Заказы и выручка — только из серверного `order_paid`.

## Что заложено в данные

- **Два устройства и анонимные строки.** 10 619 устройств и аккаунты, которых видел только сервер, после склейки дают 10 413 человек: 6 357 аккаунтов и 4 056 устройств без входа. Двумя устройствами пользуются 430 человек.
- **Блокировщики.** У части устройств на сайте клиентские события не доходят вовсе. Покупателей 4 245, и 220 из них видны только по серверным событиям. Клиентский `purchase` пришёл на 8 940 заказов из 9 717.
- **Боты.** Шесть устройств на сайте, 8 816 строк без дублей: карточки товаров раз в несколько секунд, без входа. После очистки от дублей и ботов в журнале остаётся 303 162 строки.
- **Старые аккаунты.** 1 801 аккаунт зарегистрирован в октябре — декабре 2025 года, до начала журнала; 1 340 из них появляются в журнале. Это не новички января: когорту аккаунта берут по дате регистрации.
- **Никто не уходит насовсем.** В генераторе у каждого человека остаётся небольшая вероятность зайти в любой день. В настоящем продукте часть людей уходит навсегда.
- **Релиз 3.0 — 16 марта.** Новый онбординг и оформление заказа в приложении: у когорт после релиза плато удержания выше, 19,1% против 15,5%.
- **Рекламная кампания — с 6 апреля по 3 мая.** Когорты вдвое больше, но возвращаются хуже: DAU растёт, удержание — нет.
- **Баг оплаты в Android 3.2 — с 1 июня**, исправлен 8 июня. Выручка недели 1–7 июня падает с 2 003 150 до 1 740 490 ₽, неудачных оплат в Android 142 против 10 неделей раньше.
- **Канал и платформа связаны.** Партнёры ведут в основном на сайт и покупают охотнее всех, реклама — в приложение. Отсюда парадокс Симпсона в воронке.

## Как подключиться

Код страниц запускается из корня папки с материалами:

```python
import pandas as pd
ev = pd.read_parquet("data/events/events.parquet")
users = pd.read_csv("data/events/users.csv", parse_dates=["signup_time"])
```

Файлам `.sql` со страниц нужен PostgreSQL 16 с базой `events`. Загрузка, тоже из корня материалов:

```
python -m gzip -d data/events/events.csv.gz
createdb events
psql -d events -f data/events/load_pg.sql
```

Первая команда распаковывает журнал в `data/events/events.csv` (31 МБ); сжатый файл остаётся на месте. В Linux и macOS вместо `python` пишите `python3`.

Чтобы пересобрать данные: `python data/events/gen.py`, около 20 секунд. `events.parquet` и `users.csv` совпадут с файлами набора побайтно, в `events.csv.gz` те же строки.
