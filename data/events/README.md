# Учебный журнал событий для темы 09 «Продуктовые метрики и события»

Тот же интернет-магазин товаров для дома, что в темах 02–08: каталог из 32 товаров (`data/shop`), но теперь у магазина есть приложение (Android, iOS) и сайт, и всё, что люди делают, падает строками в журнал. Сгенерировано `gen.py`, seed 909; файлы и генератор не меняйте. На страницах называем данные учебными. Журнал пригодится и в темах 10 (юнит-экономика) и 11 (A/B-тесты).

Период — 25 полных недель, с понедельника 5 января по воскресенье 28 июня 2026 года.

## Файлы

| файл | что внутри |
|---|---|
| `events.parquet`, `events.csv.gz` | журнал: 316 518 строк, 15 столбцов, одинаковые данные в двух форматах. pandas читает оба (`read_parquet`, `read_csv`), DuckDB — прямо из файла: `SELECT … FROM 'events.parquet'` |
| `users.csv` | 6 883 аккаунта: `user_id`, `signup_time` (UTC), `country`, `acquisition_channel` (органика / реклама / партнёры), `signup_platform` |
| `load_pg.sql` | загрузка в PostgreSQL 16. В песочнице база уже загружена: `psql -h /tmp -U postgres -d events` |
| `gen.py` | генератор |

## Столбцы `events`

| столбец | что это |
|---|---|
| `event_id` | id события. **Не уникален:** 4 540 клиентских событий (≈1,5 %) пришли дважды с тем же `event_id` |
| `event_time` | время в **UTC** (`2026-05-12T16:49:20Z`) |
| `event_name` | имя события, см. план событий ниже |
| `origin` | `client` — прислало приложение или сайт; `server` — записал сервер магазина |
| `anonymous_id` | id устройства (`d_…`), живёт с установки приложения или с cookie сайта. У серверных событий пусто |
| `user_id` | id аккаунта (`u_…`). Пусто, пока человек не вошёл на этом устройстве |
| `platform` | `android`, `ios`, `web` |
| `app_version` | версия приложения; у сайта пусто |
| `country` | BY, RU (UTC+3), KZ, UZ (UTC+5) |
| `traffic_source` | только у `app_open`: `search`, `direct`, `ad`, `partner`, `push`, `email` |
| `product_id`, `category`, `price` | у `product_view` и `add_to_cart` (товары из `data/shop`) |
| `order_id` | у `order_paid` и `purchase` |
| `revenue` | сумма корзины, ₽: у `checkout_start`, `order_paid`, `payment_failed`, `purchase` |

## План событий

| событие | откуда | когда |
|---|---|---|
| `app_open` | client | открыл приложение или зашёл на сайт; свойство `traffic_source` |
| `product_view` | client | открыл карточку товара |
| `add_to_cart` | client | положил товар в корзину. ≈10 % сессий начинаются с «быстрого добавления» из каталога — без карточки товара |
| `sign_up` / `login` | client | регистрация / вход; с этого события у устройства появляется `user_id` |
| `checkout_start` | client | начал оформление; без аккаунта нельзя, поэтому перед ним бывает `sign_up` или `login` |
| `order_paid` | **server** | оплата прошла — **источник правды о заказах и выручке** |
| `payment_failed` | server | оплата не прошла; часть людей пробует ещё раз |
| `purchase` | client | экран «Спасибо за заказ», через 1–4 с после `order_paid` |

## Что заложено

**Идентификация.** Человек = аккаунт. Часть людей заходит с двух устройств, из приложения и с сайта; на втором устройстве события анонимны до входа. Склейка: `anonymous_id → user_id` по любому событию устройства, где `user_id` не пуст; у кого входа не было, человек = устройство. После склейки получается 10 413 человек:
- 6 357 с аккаунтом;
- 4 056 анонимных устройств — люди без аккаунта и вторые устройства тех, кто на них не входил;
- 4 % людей (7 % аккаунтов) склеены из двух устройств и больше.

**Блокировщики.** У ≈12 % устройств на сайте клиентские события не доходят вовсе, а серверные доходят. Покупателей (людей с `order_paid`) 4 245, и 220 из них — все с сайта — видны только по серверным событиям. Клиентский `purchase` против серверного `order_paid` (без дублей): Android 0,961, iOS 0,959, сайт 0,875, всего 8 940 против 9 717 (0,92). В приложении ≈4 % `purchase` теряются: приложение закрыли раньше отправки.

**Боты.** 6 устройств на сайте: `d_1491e7f2`, `d_5f53d378`, `d_16b1367f`, `d_4715e4ee`, `d_a9034d05`, `d_0f6dfd9a` — 8 939 строк (8 816 без дублей), в основном `product_view` каждые 1,5–4 с, без входа. Правило: больше 100 клиентских событий за сутки по UTC (у людей максимум 40 без дублей).

**Старые пользователи.** 1 801 аккаунт зарегистрирован в октябре — декабре 2025, до начала журнала (1 340 из них появляются в журнале). **Ловушка:** если когорту брать по первому событию в журнале, они станут «новичками января». Для аккаунтов когорта — по `users.signup_time`.

**Никто не уходит насовсем.** В генераторе у каждого человека остаётся небольшая вероятность зайти в любой день, поэтому скользящее удержание январских когорт доходит до ~78 %, а треть «ушедших» по правилу 28 дней потом возвращается. Это свойство учебных данных; в настоящем продукте часть людей уходит навсегда.

**Сессии.** В 15 % сессий (по порогу 30 минут) есть пауза от 5 до 30 минут. По всему журналу (без дублей и ботов, по устройству): порог 30 минут — 57 267 сессий, 5 минут — 66 895 (+17 %).

**Время и «день».** Время — UTC, а люди живут в UTC+3 и UTC+5: первые события журнала — вечер 4 января по UTC. Числа ниже считаны по минскому дню (UTC+3). Последнее событие — 29 июня в 02:18 по Минску, так что этот день неполный — его отбрасываем, как и минский вечер 4 января.

**Сюжеты по датам:**
- **16 марта, релиз 3.0** (Android и iOS). Новый онбординг и новое оформление заказа: в приложении доля начавших оформление выше в 1,2 раза, у когорт приложения после релиза плато удержания выше. Устройства обновляются с задержкой, в среднем 3 дня.
- **6 апреля — 3 мая, рекламная кампания.** Около 230 лишних новичков в неделю, в основном установки приложения. Покупают и возвращаются они хуже: DAU растёт, удержание — нет.
- **4 мая, iOS 3.1** — ни на что не влияет.
- **1 июня, Android 3.2 с багом оплаты.** У обновившихся проходит только ≈15 % оплат. Исправлено в 3.2.1 8 июня, хвост тянется в неделю 8–14 июня, пока не обновились все.
- **Канал и платформа связаны.** Партнёры (кешбэк-сервисы) на 85 % ведут на сайт, и покупают эти люди охотнее всех. Реклама на 80 % — установки приложения. В приложении оформлять заказ удобнее. Отсюда парадокс Симпсона ниже.

## Проверенные числа

Везде ниже: без дублей `event_id`, без ботов, человек склеен по аккаунту, день — минский. Считано в pandas 3.0.5; число сессий — ещё и в PostgreSQL.

**Активность.** DAU в среднем за месяц: январь 134,3, февраль 172,3, март 206,6, апрель 302,0, май 339,3, июнь 386,5 (точнее 386,46 — при округлении до целых это 386, а не 387). MAU: 1 807 → 2 377 → 3 057 → 4 592 → 4 919 → 5 239. Липкость DAU/MAU — 0,066–0,074. Если считать только события с `user_id`, без склейки и анонимов, DAU в 0,70 раза меньше.

**Удержание** — недельное классическое: доля когорты, активной в неделю *n*. Когорта — неделя первого события; старые аккаунты исключены.
- Неделя 1: 27–39 %, у когорт кампании (6–27 апреля) — 28–31 %.
- Плато (недели 4–9) у когорт до релиза: ≈12–19 %.
- Плато у когорт 16–30 марта: ≈15–22 %, у их пользователей приложения — 20–27 %.

**Воронка** `app_open → product_view → add_to_cart → checkout_start → order_paid`. Новички мая — 1 610 человек с первым `app_open` в мае по Минску (старые аккаунты исключены); окно отсчитывается от первого `app_open`.

| окно | любой порядок | строгий порядок |
|---|---|---|
| 1 сутки | 14,1 % | 11,9 % |
| 7 суток | 20,4 % | 18,0 % |
| без окна (до 28 июня) | 30,4 % | 28,2 % |

Единица — сессия (30 минут): все пять шагов, где последний — клиентский `purchase`, есть в 10,8 % сессий. Строгий порядок срезает тех, у кого товар оказался в корзине раньше первой карточки: «быстрое добавление».

**Парадокс Симпсона в воронке.** Берём новичков с первым `app_open` до 22 июня по Минску. Конверсия — доля тех, у кого был `order_paid` в течение 7 суток после первого `app_open`. Сегменты — по `traffic_source` и `platform` первого `app_open`; `search` и `direct` считаем органикой.
