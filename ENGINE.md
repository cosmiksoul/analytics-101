## Файлы страницы `pages/<id>/`

- `meta.json` — `title` (имя страницы в 2–4 слова, без пояснений после тире), `description` (одно предложение), `file` (`da-1-k-латиница`).
- `article.html` — всё содержимое `<article>`: eyebrow, h1, lead, пилюли, секции. Без `<html>`, `<head>`, `<script>`.
- `page.js` — IIFE, которая кладёт данные в `window.PAGE`.
- `page.css` — стили сцены и интерактива этой страницы.

Сборка: `python3 build.py <id>` → `dist/artifact/<file>.html` (для публикации) и `dist/standalone/<file>.html`. Лимит — 250 КБ standalone.

## Порядок разделов (единый для всех страниц)

`idea` 01 Идея: главный абзац (основная мысль в 3–4 предложениях) → `<div class="scene" id="scene" aria-label="…"></div>` и `<p class="scene-hint">` прямо внутри секции idea → подробности идеи → `task` 02 Задача → метод с главным интерактивом (один или несколько h2) → нюансы → ограничения → `code` Код → `check` Проверь себя → `glossary` → `materials` → `sources` (без номера).

Каждая секция: `<section data-sec="id" data-title="Короткое имя">` + `<h2 id="id"><span class="sn">0N</span>Заголовок</h2>`. Нюансы и ограничения — отдельные секции; нюансы удобно давать выносками `.callout`. Секции «Глоссарий», «Материалы», «Источники» скопируйте из 1.1 и поменяйте только текст про NotebookLM и список источников.

## Разметка внутри текста

- Термин: `<span class="term" tabindex="0" data-g="key">слово</span>` при первом появлении. Каждый `key` должен быть в `PAGE.glossary`, и каждый ключ глоссария — встречаться в тексте.
- Сноска: `<a class="ref" href="#src-N" data-ref="src-N">N</a>`, источник — `<li id="src-N">` в секции sources, у каждого одно предложение «зачем он здесь».
- Интерактив: `<div class="block wide" data-w="name"></div>`; код: `<div class="block wide" data-code="name"></div>`; вопрос: `<div class="check" data-q="qN"></div>`.
- Вопрос-предсказание `q1` стоит прямо перед главным интерактивом, остальные — в секции `check`.
- Таблица: `<div class="tbl"><table>…</table></div>`; выноска: `<div class="callout"><p><b>Заголовок.</b> Текст</p></div>`; формула: `<div class="formula"><span class="f">…</span><small>расшифровка</small></div>`; подзаголовок внутри секции: `<h3 class="sub-h">`.
- Неразрывные пробелы `&nbsp;` после коротких предлогов и союзов, между числом и единицей.

## `window.PAGE`

```js
window.PAGE = {
  id: 'da-1-2', short: 'DA-01',
  title: 'Полное название страницы из программы',
  where: 'блок «Дата аналитика», тема 01 «Python для анализа», страница 1.2',
  aiData: 'на каких данных примеры страницы — одной фразой для промптов ИИ',
  scene: { parts, steps, hud, legend, info, aiNote, mount(root, api) { return { render(k, p) {} }; } },
  widgets: { name: (box, api) => ({ describe() { return 'состояние интерактива одной строкой для промпта ИИ'; } }) },
  code: { name: { title, badge, lang: 'python'|'sql'|'bash'|'text', code, out, outLabel?, note? } },
  questions: { q1: { sec, title?, q, code?, lang?, opts: [['текст'], ['верный', 1], …], why } },
  glossary: { key: { t, en, d } },
  materials: [['файл', 'что в нём']],
  prompts: [['Название', 'текст промпта для NotebookLM']]
};
```

- **Сцена-плеер** (правило 3 брифа): 8–12 шагов в 4–6 частях. `parts: [{n:'01', name, s:[индексы шагов]}]`, `steps: [{title, body (HTML, 1–2 коротких абзаца), dur (мс)}]`. `mount(root, api)` рисует в `root` (тёмная сцена, переменные цвета `--s-bg`, `--s-ink`, `--s-ink2`, `--s-mut`, `--s-acc`, `--s-line`) и возвращает `render(k, p)`, где `k` — шаг, `p` — прогресс шага 0…1. `render` вызывается каждый кадр: собирайте состояние детерминированно из `k` и `p`, перерисовывайте DOM только когда состояние изменилось. Счётчики — `api.hud(id, значение, подпись)` для `hud: [{id, label}]`. Нужны выноски к объектам (см. `.nb-call` в 1.1). Сцена должна читаться на ширине 360 px: `@container (max-width: 760px)`.
- **Интерактив**: функция получает пустой `box` и `api` (`$`, `esc`, `fmt`, `plural`, `hl`, `copy`, `css`). Состав: `.block-hd` с названием `<span class="t">… <i>интерактив</i></span>` и кнопками, строка «что сделать» (`p.hint`), рабочая область, строка состояния `.status` с метрикой, кнопка «Сбросить». Детерминированно, без случайностей без зерна. На 360 px может упрощаться, но не исчезать. Используйте классы прототипа: `.stage`/`.narr`, `.tabs`, `.seg`, `.ctrls`, `.status`, `.readout`, `.btn`, `.btn.ghost`, `.btn.small`. Цвета — только токены (`--ink`, `--surface`, `--accent`, `--good`, `--bad`, `--line`…), иначе сломается тёмная тема.
- **Вопросы**: 5–7, в `questions` каждая запись с отступом ровно 4 пробела (`    q1: {`) — по нему сборщик считает вопросы. Один вопрос по сцене, один по строке кода (`code`), у каждого разбор `why`: почему верный верен и чем плохи остальные.
- **SQL** (тема 03 и дальше): учебная база и правила запуска — `data/shop/README.md`.
- **Код**: всё, что на Python, запустите в песочнице (`python3`, есть numpy 2.5.3, pandas 3.0.5, Python 3.13.18) и вставьте настоящий вывод. Бейдж — `проверено: Python 3.13` (или с версией библиотеки). Если вывод сокращён, скажите это в `outLabel`. Данные кода — те же, что в сцене или интерактиве.

## Уроки первой пачки

- Главный абзац «Идеи» — основная мысль страницы в 3–4 предложениях, понятная без остального текста; сцена стоит сразу под ним и показывает именно эту мысль. Подсказка к термину — при первом появлении в порядке чтения: лид и главный абзац идут первыми.
- Каждое новое понятие объясняйте при первом появлении, даже бытовое для программиста: автор просил раскрывать такие понятия.
- Не называйте свои классы `.lg`, `.sm` и другими короткими именами из `base.css` — они скрываются на узких экранах. Используйте префикс страницы.
- Шрифт абзацев статьи протекает в сцену: текст сцены стилизуйте селекторами вида `.scene .ваш-класс`.
- Высоту сцены на телефоне при необходимости поднимайте в `page.css`: `@container (max-width: 860px) { .scene .sc-stage { height: …px; } }`.
- В исходниках нельзя оставлять символ замены U+FFFD (�): публикация артефакта его отклоняет. Нужен такой символ — пишите `\uFFFD` в JS и `&#xFFFD;` в HTML.
- Слова считайте по `tools/shot.js`, он учитывает сцену, вопросы и глоссарий.

## Уроки второй пачки

- Лигатуры моноширинного шрифта отключены в движке с `!important`; правила в `page.css` для этого больше не нужны.
- Короткое имя `.pr` тоже занято в `base.css` (как `.lg` и `.sm`): только классы с префиксом страницы.
- `.sc-info` в правом верхнем углу сцены наезжает на счётчики HUD с длинными значениями: держите значения короткими или прячьте `.sc-info` на узкой сцене в `page.css`.
- В pandas 3 строки по умолчанию хранит pyarrow, и регулярные выражения в `.str` идут через RE2: `\w` там только латиница, цифры и `_`. Шаблон `[^\w\s]` стирает кириллицу целиком — перечисляйте буквы явно (`[^0-9A-Za-zА-Яа-яЁё\s]`) и говорите об этом в тексте, если код чистит строки.
- `.tbl td:first-child` не переносится; для широких таблиц на 360 px переопределяйте это в `page.css`.
- Слова: `qa.js` считает только статью, `shot.js` — статью со сценой, вопросами и глоссарием; ориентир — `shot.js`.

## Уроки третьей пачки

- В `base.css` заняты и другие короткие имена: `.out`, `.num`, `.on`, `.ok`, `.n`, `.steps`. Префикс страницы обязателен для всех своих классов.
- Сборщик считает вопросы по любой строке вида `    qN:` в `page.js` — не называйте так ключи кода и других объектов.
- Временные файлы — только в своей подпапке scratchpad (`scratchpad/<id>/`): параллельные агенты делят общий scratchpad.
- Подсветка SQL знает оконные функции, рамки, FILTER, ROLLUP, EXISTS, DATE_TRUNC и т. п.; соседние сноски движок разделяет запятой; лигатуры в сцене и интерактивах отключены движком.
- Вывод psql на телефоне: `.out pre` переносит строки, для широких таблиц ставьте в `page.css` `white-space: pre; overflow-x: auto`.

## Уроки четвёртой пачки

- Движок больше не сбрасывает сцену на шаг 0, если по шагам уже щёлкали; стрелки ← → не листают сцену, когда фокус внутри интерактива (`.block`); при изменении размера сцены движок заново вызывает `render` текущего шага.
- Подписи HUD и заголовки табло переводятся в верхний регистр: греческие буквы (η, θ, λ) превращаются в похожие на латиницу заглавные. Пишите словами.
- `shot.js` считает текущий шаг сцены и текущий текст интерактива, разборы вопросов — нет. Держите запас 100–200 слов до 3 000.
- Перетаскивание на телефоне: `touch-action: none` только на самой ручке, а не на всём графике, иначе страница не прокручивается.

## Материалы страницы

Список `PAGE.materials` в черновике предварительный: что прилагается к странице и в какой форме с этим работают (ноутбук, `.sql`, скрипт, данные). Файлы не создаются — состав и файлы готовятся на вычитке, по главе целиком. Не обещайте того, что никто не будет делать: упражнения и демо — только если без них страница теряет смысл.

Генераторы данных и всё, без чего нельзя воспроизвести вывод кода, кладите в папку страницы (`pages/<id>/data/`), а не в scratchpad: scratchpad временный.

## Уроки пятой пачки

- Заголовки таблиц `.tbl th`, подписи HUD и табло переводятся в верхний регистр: σ становится Σ, μ — Μ. Оборачивайте такие символы в `<span class="nocase">σ</span>` или пишите словами.
- Scratchpad — сессионная папка из окружения агента (`…/scratchpad/<id>/`). Всё, что нужно для воспроизведения, — в `pages/<id>/data/`.
- Удобный приём: генератор в `pages/<id>/data/` считает данные сцены и вывод кода и вписывает их в `page.js` между метками (`/*data:start*/ … /*data:end*/`). Повторный запуск даёт тот же файл.
- Экспорт в Markdown не понимает `<sup>`: степени в тексте вопросов и глоссария пишите как `1e-6` или словами.
- На узкой сцене высокий HUD перекрывает верх `.sc-html`: поднимайте отступ в `page.css`.

## Уроки восьмой пачки (визуализация)

- В теме 08 код рисует графики, и их настоящий вывод — картинка. Вставляйте его рисунком под блоком кода в `article.html` (`<figure class="<префикс>-fig">` с подписью «вывод кода выше»). Предпочтительно SVG из самого Matplotlib (`rcParams['svg.fonttype'] = 'none'`, текст остаётся текстом; упрощайте данные), иначе PNG/WebP до ~40 КБ. Следите за лимитом 250 КБ на страницу.

Правило `svg text { font-family: var(--mono) }` в `base.css` делает моноширинными подписи встроенных SVG — переопределяйте в `page.css`.

## Материалы страниц (с ноября 2026, глава 01)

- Сборка: `python3 tools/build_materials.py <id> [<id> …]`, затем `python3 tools/build_materials.py --index`. Результат — `dist/materials/<файл-страницы>/`, архив `<файл-страницы>.zip` и `index.json` (путь, размер, описание — для ссылок в `buildMaterials()`).
- Сценарий страницы — `pages/<id>/materials/build.py` с функцией `build(m)`; рядом лежат исходники: скрипты, данные, ноутбуки в формате `.nb.py`. Объект `m` (класс `Mat` в `tools/matlib.py`) умеет:
  - `m.script(имя, ключ)` — блок кода страницы → файл `.py`, запуск, сверка вывода со страницей;
  - `m.take(имя)` — скопировать готовый файл или папку; `m.put(имя, данные)` — записать;
  - `m.run([...], expect=…, mode=…)` — запустить команду в рабочей копии и сверить вывод (`exact`, `contains`, `within`);
  - `m.said(имя)` — скрипт с блоком «# Вывод:» в хвосте: вывод сверяется с этим блоком;
  - `m.notebook(имя, исходник, "main" | "solutions")` — собрать и выполнить ноутбук;
  - `m.check(что, условие)` — своя проверка.
- Исходник ноутбука `.nb.py`: ячейки начинаются с `# %%`. `[markdown]` (можно `main` или `solutions`), `page:<ключ>` (заголовок, код и примечание блока со страницы; вывод сверяется дословно), `code` (своя ячейка; `within:<ключ>` — её вывод должен быть частью вывода страницы), `exercise`, `solution`, `check`.
- Основной ноутбук выполняется до первого упражнения, у заготовок вывода нет. Ноутбук с решениями выполняется целиком. Отдельным прогоном проверяется, что нетронутая заготовка даёт `AssertionError` с сообщением, а не `NameError`.
- Список материалов на странице (`PAGE.materials`) — источник правды: сборка падает, если файла из списка нет или в папке лежит файл не из списка. `README.md` папки пишется сам.
- Имена переменных в упражнениях: не заводить на верхнем уровне `r`, `late` и другие имена, отсутствие которых блоки страницы проверяют через `globals()`.
- Размеры файлов на странице писать с «около», если число зависит от единиц (МБ десятичные и двоичные): `orders_big.csv` — 23,5 млн байт, это 23,5 или 22,4 МБ.
- Ядро Jupyter печатает предупреждение `IPKernelApp … without encryption` — оно безвредно.
- Ячейка `# %% page:<ключ> within` — на странице вывод длиннее, чем даёт ячейка (пример: блок 2.1 с выводом сразу двух версий pandas). Ячейка `# %% page:<ключ> ~ <regex>` — маска для того, что меняется от запуска к запуску: совпадения заменяются на «#», пробелы схлопываются, остальное сверяется дословно. Для замеров: `~ \d+\.\d+ мс`.
- `m.extra = "…"` в сценарии страницы дописывает абзацы в README папки: порядок запуска, переменные окружения (пример — 2.2 с учебным сервером).
- Сценарий может поднимать свои процессы: 2.2 запускает `api_server.py` из рабочей копии и гасит его в `finally`. Между запусками скриптов, которые ходят в этот сервер, нужна пауза 2,5 с — иначе первый запрос получает 429 и вывод расходится со страницей.
- PostgreSQL в песочнице останавливается между сессиями. Сценарий 2.2 проверяет поведение на PostgreSQL, только если сервер поднят; иначе печатает «проверка пропущена». Перед сборкой 2.2 и перед главами 03, 09–11 сервер надо запустить.
- Блок кода, который переопределяет `warnings.showwarning` (2.1, цепочки присваивания), меняет показ предупреждений до конца ноутбука: ставить его последним среди блоков страницы.
- **Общие наборы данных** (с главы 03). `python3 tools/build_shared_data.py <набор>` кладёт `data/<набор>/` в `dist/materials/data/<набор>/` и делает архив `data-<набор>.zip`. README для читателя — `data/<набор>/README.reader.md`; `README.md` там же остаётся для авторов страниц. Список файлов и проверки набора — в словарях `SETS` и `CHECKS` скрипта.
- В сценарии страницы `m.use_data("shop")` подключает общий набор: в рабочей копии он лежит как `data/shop/`, в папку страницы не копируется. Строка «data/shop/» в списке материалов страницы считается выполненной, если набор собран. `m.versions = "…"` заменяет строку о версиях в README.
- SQL через psql: `m.run(["psql", "-f", "q1.sql"], expect=…, sub="queries", code=None, merge=True)`. `merge=True` пишет ошибки в общий поток с выводом, иначе порядок строк не совпадёт со страницей. `stdin="файл.sql"` подаёт файл на вход: так psql печатает ошибку без префикса с именем файла. Подключение песочницы задаётся в сценарии: `PGHOST=/tmp`, `PGUSER=postgres`, `PGDATABASE=shop`.
- Несколько блоков SQL одним файлом: ожидаемый вывод — выводы блоков через пустую строку. Номер `LINE N` в сообщении об ошибке psql считает от начала запроса, и комментарий перед запросом в него может войти, а может нет: см. сценарий 3.5.
- Упражнения по SQL: `DROP VIEW IF EXISTS exN; CREATE TEMP VIEW exN AS <заглушка с нулём строк>` и проверочный `SELECT CASE … 'верно' … 'не сошлось' END`. Сборка проверяет: нетронутый файл — все «не сошлось» без ошибок, файл решений — все «верно».
- **Ноутбук и общий набор** (с главы 04). У читателя ноутбук лежит в папке страницы, а `data/` — уровнем выше, и относительный путь `data/clients/clients.csv` из ноутбука не находится. ## Курс целиком: структура, главная, оглавление, публикация (ноябрь 2026)

- **Название курса — «Аналитика 101»** во всех текстах, материалах и промптах; «учебник по данным» больше не используем.
- **Структура курса — `engine/course.json`.** Его генерирует `tools/make_course.py` из программ блоков (папка проекта) и `meta.json` страниц: модули, темы, страницы с заголовком h1, коротким названием и временем чтения, описания тем (`LEADS`) и лид главной (`COURSE_LEAD`). Из него `build.py` собирает боковину (живые ссылки на страницы темы и первые страницы других тем), хлебные крошки и ссылку «Оглавление курса →» на тему. Новую страницу сначала добавить в `pages/`, потом перегенерировать `course.json`.
- **Блокноты NotebookLM — `engine/notebooks.json`**, ключ `da-NN`. Пока `url` пустой, пункт «NotebookLM» в меню «Обсудить с ИИ» серый с пометкой «скоро», а в «Материалах» вместо ссылки стоит название блокнота. Кнопку «Скопировать страницу в Markdown» из меню убрали, она осталась в «Материалах».
- **`window.A101`** вшивает `build.py`: ключ отметок «пройдено» (`a101-done`) и карта материалов страницы из `dist/materials/index.json`. Ссылки на материалы относительные (`materials/…`).
- **Сайт** собирает `tools/build_site.py` в `site/`: `index.html` (главная), `course.html` (оглавление с отметками), `404.html`, страницы и `materials/`. Стили и скрипт этих трёх страниц — `engine/site.css` и `engine/site.js`, токены и шапка берутся из `base.css` до блока «каркас». Проверка ссылок — `tools/check_site.py`. Публикация на GitHub Pages — `DEPLOY.md`.
- **Markdown страниц** — `tools/export_md_all.py materials` (в папки материалов, затем `build_materials.py --index`) и `tools/export_md_all.py notebooklm` (папки тем для блокнотов: страницы с ответами и разборами и файл «Данные и материалы темы»). Заголовок в Markdown и промптах — h1 страницы.
