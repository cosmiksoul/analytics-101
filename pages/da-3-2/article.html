В таблице магазина 60 клиентов. После соединения с заказами в отчёте оказалось 239 строк. Откуда они взялись? В этом уроке вы разберёте, какие строки возвращает каждый тип JOIN, как заранее оценить их число и как проверить, не посчитали ли вы один заказ несколько раз.

01Как соединение образует пары строк

Соединение (JOIN) позволяет сопоставить строки двух таблиц. Например, по ключу соединения customer_id можно найти заказы каждого клиента. Клиент с тремя заказами встретится в результате трижды. А попадёт ли в результат клиент без заказов, зависит от типа соединения. При LEFT JOIN строка клиента сохраняется, а в столбцах заказа стоит NULL. В анимации диаграмма Венна показывает, какие ключи есть в обеих таблицах. Чтобы узнать число строк, посчитаем все подходящие пары.

Переходите между шагами кнопками или стрелками ← и → на клавиатуре.

Как записывается соединение

JOIN записывают в разделе FROM. В логическом порядке запроса сначала формируется результат соединения, а затем к нему применяется WHERE. Этот порядок мы разбирали в уроке 3.1.

В записи FROM customers AS c LEFT JOIN orders AS o ON o.customer_id = c.customer_id к каждому клиенту присоединяются его заказы. Буквы c и o после AS — псевдонимы таблиц. По ним видно, из какой таблицы взят одноимённый столбец. После ON записывают условие соединения. Здесь оно требует совпадения номеров клиентов. JOIN без уточнения означает INNER JOIN. Названия LEFT JOIN и LEFT OUTER JOIN равнозначны1.

Пять типов соединения

Внутреннее соединение INNER JOIN возвращает пары строк, для которых выполнено условие. Внешние соединения добавляют строки без пары из левой таблицы (LEFT), правой (RIGHT) или обеих (FULL). При перекрёстном соединении CROSS JOIN каждая строка первой таблицы образует пару с каждой строкой второй1. В таблице ниже приведены результаты для пяти клиентов и семи заказов из анимации.

ТипЧто остаётсяСтрок
INNER JOINтолько пары5
LEFT JOINпары и клиенты без заказов, справа NULL7
RIGHT JOINпары и заказы, чьих клиентов нет в выборке, слева NULL7
FULL JOINпары и строки без пары с обеих сторон9
CROSS JOINвсе сочетания строк35

Если поменять таблицы местами, RIGHT JOIN можно записать как LEFT JOIN и получить те же пары при том же условии. CROSS JOIN подходит, например, для отчёта по дням и каналам: сначала строят все сочетания, а затем ставят нули там, где заказов не было. Запись FROM a, b без условия тоже вернёт все сочетания, даже если вы хотели сопоставить строки по ключу.

Почему трём общим ключам соответствуют пять строк

На диаграмме Венна каждый номер клиента представлен один раз. В таблице заказов номер может повторяться. Одному клиенту соответствует несколько заказов. Такую кардинальность связи называют «один ко многим». Если у клиента три разных заказа, в результате будет три строки с его именем. Такое размножение строк само по себе ещё не означает, что в данных есть ошибка.

Для INNER JOIN удобно посчитать пары отдельно для каждого ключа. Если одно значение встречается дважды слева и трижды справа, то при соединении по равенству оно даст шесть пар. Затем результаты для всех ключей складывают. Во внешнем соединении к ним добавляют строки без совпадения1.

строк = Σk nL(k) · nR(k) + строки без парыдля каждого непустого значения ключа умножьте число строк слева на число строк справа. При внешнем соединении прибавьте строки без совпадений с сохраняемой стороны

Где поставить условие об оплате

При INNER JOIN условие o.status = 'paid' даёт один и тот же результат в ON и в WHERE. При LEFT JOIN место условия важно. В ON оно определяет, какие заказы можно присоединить к клиенту. Если таких заказов нет, клиент всё равно останется в результате. В WHERE то же условие проверяется для уже полученных строк. Сравнение NULL = 'paid' даёт UNKNOWN («неизвестно») согласно трёхзначной логике SQL. WHERE оставляет только строки, для которых условие истинно2.

На нашей выборке условие об оплате в ON даёт шесть строк: четыре оплаченных заказа и две строки клиентов без заказа за выбранные дни. Все пятеро клиентов попали в отчёт. Если перенести условие в WHERE, останутся только четыре строки с заказами1.

Самосоединение и составной ключ

При самосоединении одна таблица участвует в запросе дважды. В customers.referrer_id записан номер клиента, по приглашению которого зарегистрировался другой клиент. Псевдоним c обозначает приглашённого, а r — того, кто его пригласил: customers AS c JOIN customers AS r ON r.customer_id = c.referrer_id3.

Первичный ключ таблицы order_items состоит из двух столбцов, order_id и product_id. Вместе они определяют одну позицию заказа. Такой ключ называют составным. В истории статусов order_status_log уникальна другая пара: order_id и status. При соединении только по номеру заказа получим всю историю, 483 строки. Если добавить в ON совпадение статуса через AND, останется только запись о текущем статусе каждого из 231 заказа.

Как найти клиентов без заказов

Чтобы найти клиентов без заказов или товары без продаж, нужны строки, для которых в другой таблице нет пары. Такую операцию называют антисоединением. Её можно записать несколькими способами4.

  • LEFT JOIN … WHERE o.order_id IS NULL оставит клиентов без заказов. Для проверки выберите столбец, который в существующей строке всегда заполнен, например первичный ключ заказа. Условию o.promo_code IS NULL удовлетворял бы и настоящий заказ без промокода.
  • В выражении NOT EXISTS (SELECT 1 FROM orders AS o WHERE o.customer_id = c.customer_id) внутренний запрос ссылается на номер клиента из внешнего запроса. Такой подзапрос называют коррелированным. Условие NOT EXISTS истинно, если у этого клиента нет ни одного заказа5.
  • c.customer_id NOT IN (SELECT customer_id FROM orders) годится, когда в списке номеров нет NULL. Ниже разберём, что изменит гостевой заказ без номера клиента.
  • EXCEPT возвращает номера клиентов из первого запроса, которых нет среди номеров из второго, и убирает повторы6. Чтобы вывести ещё и имена, их нужно будет получить по этим номерам.

02Отчёт по клиентам и заказам

Отделу маркетинга нужны отчёт по суммам заказов и список клиентов без заказов для рассылки промокодов. В базе 60 клиентов. После соединения с заказами в отчёте оказалось 239 строк. Когда в него добавили позиции заказов и снова сложили суммы заказов, вместо 1 051 380 ₽ получилось 2 069 300 ₽. А при внутреннем соединении клиентов со справочником стран из результата исчезли два человека.

Чтобы объяснить эти расхождения, выясним, что представляет одна строка на каждом шаге: клиента, заказ или отдельную позицию заказа. Сумму нужно считать на том уровне, к которому она относится.

03Как проверить число строк

Сначала выясните, повторяются ли значения ключа. Для непустого ключа достаточно сравнить count(ключ) и count(DISTINCT ключ). Первый показатель учитывает повторы, второй считает каждое значение один раз. Разность count(*) - count(ключ) покажет, сколько строк содержат NULL в этом столбце. В orders 231 заказ и 52 разных номера клиента. Затем решите, нужны ли вам клиенты без заказов: от этого зависит выбор между INNER и LEFT JOIN.

В выборке из анимации номерам 105, 106 и 114 соответствуют 1, 3 и 1 заказ. Получится пять пар. LEFT JOIN добавит двух клиентов без заказов, всего семь строк. После запуска проверьте оба числа: count(*) даст число строк, а count(DISTINCT c.customer_id) — число разных клиентов.

В тренажёре используется та же выборка. На первой вкладке можно менять тип соединения, условие ON и место фильтра по статусу. На второй вы найдёте клиентов без заказов тремя способами. Прежде чем запускать запрос, попробуйте предсказать его результат.

Столбец «в итоге» показывает, сколько раз исходная строка вошла в результат. У Ульяны М. стоит ×3, потому что в выборке три её заказа. Если соединить таблицы только по channel, рядом с Фёдором Б. окажутся заказы других клиентов с тем же каналом. А если потребовать совпадения и customer_id, и channel, в результат попадут лишь пары, где канал заказа совпал с каналом привлечения его владельца.

На второй вкладке можно добавить гостевой заказ с NULL в customer_id. Посмотрите, что изменится для NOT IN, NOT EXISTS и LEFT JOIN. В основной базе магазина такого заказа нет. Как обрабатывать пропущенные ключи в pandas, разбиралось в уроке 2.4. Дополнительные упражнения по SQL есть в тренажёре SQLBolt7.

04Фильтры, NULL и порядок соединений

Оплаченные заказы и клиенты без заказов. Условие o.status = 'paid' в WHERE исключит клиента, если у него нет оплаченных заказов. Чтобы сохранить всех клиентов, укажите статус в ON. Если же отчёт нужен только по клиентам конкретной страны, поместите условие по стране в WHERE: так оно отберёт самих клиентов1.

Пропуски в ключах. Сравнение NULL = NULL даёт UNKNOWN. Две строки с пропусками в ключе при таком сравнении не составят пару. У клиентов 117 и 142 не указан код страны. INNER JOIN со справочником стран по равенству кодов вернёт 58 клиентов из 60. Если по условию задачи два NULL должны совпадать, используйте IS NOT DISTINCT FROM8. В pandas функция merge сопоставляет пропуски в ключах, и это различие стоит учитывать при переносе запроса.

NOT IN при пропуске в списке. Если в списке есть NULL, выражение x NOT IN (a, b, NULL) ложно при совпадении с известным значением и даёт UNKNOWN, когда совпадения нет. В обоих случаях WHERE исключает строку5. Для поиска клиентов без заказов можно использовать NOT EXISTS или убрать NULL из списка условием WHERE customer_id IS NOT NULL.

Порядок таблиц. Для внутренних соединений планировщик может менять порядок обработки таблиц, сохраняя результат. У внешнего соединения важно, с какой стороны нужно сохранить строки без пары: запросы a LEFT JOIN b и b LEFT JOIN a могут дать разные результаты9. Начните с основной таблицы отчёта и после каждого нового соединения проверяйте число строк.

05Как база выполняет соединение

Правила JOIN описывают результат запроса. Чтобы его получить, PostgreSQL может использовать вложенные циклы, хеш-соединение или слияние отсортированных строк. Выбор зависит, в частности, от размера таблиц и доступных индексов10.

У двух таблиц по 100 000 строк CROSS JOIN даст 10 миллиардов пар. Как читать план запроса и оценивать стоимость соединений, разбирается в теме 03 блока «Дата инженерия».

06Запросы к учебной базе

Все четыре примера работают с базой shop в PostgreSQL 16. Первый создаёт временные таблицы с выборкой из анимации и показывает число строк для пяти типов JOIN. Оператор UNION ALL объединяет результаты отдельных запросов в один список.

Второй пример четырьмя способами находит клиентов без заказов во всей базе. Затем на данных о приглашениях сравниваются NOT IN и NOT EXISTS, когда в подзапросе есть NULL. Результат EXCEPT помещён в подзапрос, чтобы пересчитать строки. Эта конструкция разбирается в уроке 3.4.

Третий пример находит пары «приглашённый клиент и его пригласивший». Затем сравнивает два способа сопоставить коды стран, когда в обеих таблицах есть NULL.

В четвёртом примере мы проверяем ключи и считаем заказы до и после соединения с их позициями. В конце сравним два условия соединения с историей статусов.
