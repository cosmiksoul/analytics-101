Группировка, сводные таблицы и соединение данных

Какую выручку за месяц принесли магазину заказы из каждой страны? Сколько выручки принёс каждый канал? Вы соберёте отчёт по этим сегментам, добавите к заказам сведения из справочника и проверите, не посчитали ли один заказ дважды.

01От заказов к выручке по странам

Одна строка выгрузки соответствует одному заказу. Сначала выберем ключ для группировки — страну и месяц — и сложим суммы оплаченных заказов в каждой группе. Получится сводная таблица с выручкой по странам за три месяца. Затем возьмём названия стран и валюты из справочника. При левом соединении по коду страны в таблице останутся все страны из отчёта. Если кода нет в справочнике, вместо названия и валюты появятся пропуски (NaN). Если один код встретится в справочнике дважды, строка отчёта тоже повторится.

Переключайте шаги кнопками под анимацией или клавишами ← и →.

Разделить, применить, собрать

Хэдли Уикем описал приём split-apply-combine как последовательность из трёх действий. Сначала разделите данные на группы, затем выполните расчёт в каждой и объедините результаты1. В pandas группы задаёт метод groupby2.

Вызов paid.groupby(["country", "month"]) задаёт группы заказов. Чтобы получить итог для каждой группы, выберите агрегирующую функцию. Например, sum складывает суммы заказов, а size считает строки. По умолчанию ключи групп образуют индекс результата. В нашей выгрузке 25 оплаченных заказов образуют 12 групп. Если сложить выручку всех групп, получится та же сумма, что и до группировки, — 79 430 ₽.

Как посчитать несколько показателей за один раз

Чтобы сгруппировать заказы сразу по стране и месяцу, передайте в groupby список из двух столбцов. Для каждой пары значений можно посчитать несколько показателей одним вызовом agg. Запись через именованные агрегаты позволяет указать для каждого показателя имя нового столбца, исходный столбец и функцию2.

Вызов agg(revenue=("amount", "sum"), orders=("order_id", "size")) даёт 12 строк. В столбце revenue хранится выручка группы, в orders — число заказов. Метод size считает все строки. Метод count пропускает строки, где в выбранном столбце отсутствует значение.

Итог для группы или значение для каждого заказа

Если сгруппировать заказы по стране и применить agg, в отчёте останутся четыре строки, по одной на страну. Для расчёта доли заказа нам нужен другой результат: в каждой из 25 строк должна стоять общая выручка по стране этого заказа. Её вернёт transform с функцией sum. Индекс останется таким же, как у исходных заказов2.

Чтобы найти долю, разделим сумму заказа на выручку по его стране: paid["amount"] / paid.groupby("country")["amount"].transform("sum"). На заказ № 1002 приходится около 21% выручки по заказам из Узбекистана (3 380 из 16 340 ₽). Другой пример — когорты по месяцу первой оплаты. Если сгруппировать оплаченные заказы по клиенту и применить к столбцу месяца transform("min"), в каждой строке появится месяц первой оплаты этого клиента в выгрузке.

02Какие данные нужны для отчёта

В файле orders.csv записаны заказы магазина. По нему посчитаем выручку по странам, месяцам и каналам и сравним когорты клиентов. Названия стран возьмём из справочника countries.csv. В файле managers.csv указано, кто отвечает за каждый канал в конкретной стране.

Проверим два места, где можно ошибиться в расчёте. При стандартных настройках groupby пропустит заказ, если значение ключа отсутствует. А если соединить заказы с менеджерами только по стране, у заказа может оказаться сразу несколько менеджеров. При подсчёте выручки сумма такого заказа попадёт в отчёт несколько раз.

После соединения сравним число строк и общую сумму заказов с исходными. Затем отдельно проверим, для каких заказов нашёлся менеджер и уникален ли выбранный ключ в справочнике. Подробнее группировку и соединение разбирают Уэс Маккинни3 и Джейк Вандерплас4.

03Длинный и широкий форматы

В длинном формате выручка каждой страны за каждый месяц занимает отдельную строку. У нас четыре страны и три месяца, всего 12 строк. В широком формате у каждой страны одна строка и три столбца с выручкой, по одному на месяц.

Хэдли Уикем предложил три правила для упорядоченных данных (tidy data). По этим правилам каждой переменной соответствует столбец, каждому наблюдению — строка, а каждому типу наблюдений — отдельная таблица5. В нашем отчёте наблюдение — выручка одной страны за месяц. В длинном формате страна, месяц и выручка занимают три отдельных столбца. В широком формате значения месяца становятся заголовками.

В широкой таблице удобно сравнивать несколько месяцев в пределах одной строки. Длинный формат пригодится для графика, где нужно явно указать столбцы для осей и цвета линий. В pandas для таких преобразований есть несколько методов6.

ПереходМетодЧто делает
длинная → широкаяpivot_tableвычисляет значение каждой ячейки с помощью aggfunc
длинная → широкаяpivotвыдаёт ошибку, если одной ячейке соответствуют несколько строк

В нашем примере pivot_table группирует заказы по месяцу и каналу и выводит каждый канал в отдельном столбце. По умолчанию метод вычисляет среднее. Для выручки нужна сумма, поэтому укажем aggfunc="sum"7. В январе у магазина нет оплаченных заказов из рассылки. В сводной таблице на этом месте будет пропуск. Поскольку мы считаем выручку от заказов, здесь уместно подставить ноль с помощью fill_value=0.

Метод pivot переносит значения в ячейки без дополнительных вычислений. Если на одну ячейку приходятся два заказа, как в январе у канала «органика», метод выдаст ошибку Index contains duplicate entries, cannot reshape. Чтобы перейти от сводной таблицы к длинной, воспользуемся melt. Из трёх строк с месяцами и трёх столбцов с каналами получатся девять строк с полями «месяц», «канал» и «выручка». Такую таблицу удобно передать в seaborn и назначить каждому каналу свой цвет8.

04Как соединить заказы с таблицей менеджеров

Метод merge находит в двух таблицах строки с одинаковым ключом. В параметре on указывают имя столбца или список имён. Если столбцы ключа в двух таблицах называются по-разному, используют left_on и right_on9. Параметр how задаёт тип соединения и определяет, что произойдёт со строками без пары10.

  • inner оставляет только совпадения и сохраняет порядок ключей левой таблицы. Это тип соединения по умолчанию.
  • left сохраняет все строки левой таблицы. Если совпадения нет, в столбцах правой таблицы будут пропуски.
  • right сохраняет все строки правой таблицы. Для строк без совпадения пропуски появятся в столбцах левой таблицы.
  • outer сохраняет и совпадения, и строки без пары с обеих сторон. Результат отсортирован по ключу.

Число строк зависит также от кардинальности соединения — от того, сколько строк с одинаковым ключом есть с каждой стороны. Если у каждого кода страны одна запись в справочнике, при левом соединении каждому заказу будет соответствовать одна строка. Если же в заказах три строки с кодом RU, а в таблице менеджеров таких строк две, соединение только по коду страны даст шесть комбинаций.

В интерактиве шесть заказов. В таблице менеджеров для каждой пары «страна, канал» указан один человек. Есть менеджер для Армении, хотя заказов из неё нет. А для заказа из Узбекистана в таблице менеджеров нет соответствия. Попробуйте предсказать, сколько строк получится при разных ключах.

Параметр indicator=True добавляет индикатор _merge. Значение both означает, что ключ найден в обеих таблицах, left_only — только в левой, right_only — только в правой9. Метод value_counts() подсчитает строки каждого типа в результате. Чтобы увидеть все несовпадения с обеих сторон, используйте outer. При inner строки без пары в результат не попадут.

Если соединить таблицы по country, в обеих останется столбец channel. В результате pandas различает их с помощью суффиксов: channel_x взят из заказов, channel_y — из таблицы менеджеров. Сравните каналы в этих столбцах: одного совпадения по стране недостаточно, чтобы назначить менеджера. Если в результате окажется менеджер без заказа, в order_id и amount появятся пропуски. В нашем примере эти столбцы имели тип int64 и стали float64, поэтому номер заказа выглядит как 1003.0.

Параметр validate позволяет проверить ключ во время соединения. При validate="many_to_one" ключ справа должен быть уникальным. Если он повторяется, pandas остановит операцию с ошибкой MergeError9. В таблице менеджеров проверку проходит только пара country и channel.

Как объединить несколько выгрузок с помощью concat

Функция pd.concat по умолчанию добавляет строки одной таблицы к строкам другой и сопоставляет столбцы по названиям10. Так можно собрать три месячные выгрузки в одну. Если столбец есть только в одной выгрузке, в строках другой появятся пропуски. Чтобы заново пронумеровать строки, укажите ignore_index=True. С параметром axis=1 функция разместит таблицы рядом, сопоставив строки по индексу. Проверьте повторы отдельно: если в двух выгрузках справочника есть код RU, после concat в справочнике останутся обе записи.

05Повторы, пропуски и итоги

Уникальность ключа. Допустим, слева стоит справочник стран, а справа — заказы. Параметр validate="one_to_many" проверит, что в справочнике на каждый код приходится одна запись. При повторе кода pandas выдаст MergeError. Если поменять таблицы местами, та же проверка записывается как validate="many_to_one". Параметр "one_to_one" проверяет уникальность ключа с обеих сторон9.

Пропуски в ключе. При dropna=True (по умолчанию) groupby исключает строки с пропуском в ключе. Выручка по таким заказам не войдёт в итог. Чтобы учесть их отдельной группой при группировке по стране, укажите dropna=False11. При merge пропуски в ключах, напротив, совпадают друг с другом9. Перед соединением проверьте, сколько таких строк в каждой таблице: df["country"].isna().sum().

Порядок групп. По умолчанию groupby сортирует ключи. В нашем примере это BY, KZ, RU и UZ. При sort=False порядок соответствует первому появлению в выгрузке: UZ, BY, KZ, RU. Для столбца категориального типа можно задать собственный порядок категорий. Начиная с pandas 3.0, по умолчанию действует observed=True и в отчёт входят только наблюдаемые категории. С observed=False сумма появится и для заранее заданного канала без заказов. Например, у канала «партнёры» она будет равна нулю11.

Средний чек за квартал. Параметр margins=True добавляет в сводную таблицу строку и столбец итогов. Надпись All можно изменить через margins_name7. Для расчёта итогов pandas применяет ту же функцию к исходным данным. В нашем примере средний чек за квартал равен 3 177 ₽: это выручка, делённая на 25 оплаченных заказов. Если усреднить три месячных средних, получится 3 151 ₽, потому что в таком расчёте у каждого месяца одинаковый вес.

06Когда удобнее посчитать итог в базе данных

Если в базе миллионы заказов, а для отчёта нужны всего 12 итоговых строк, можно сгруппировать заказы прямо в SQL. Тогда в pandas достаточно загрузить готовые итоги. В главе 3 вы встретите знакомые операции.

pandasSQL

При соединении по неполному ключу один заказ и в SQL может попасть в результат несколько раз. Есть различие в обработке пропусков. В SQL при обычном сравнении ключей через = два значения NULL не дают совпадения. В pandas строки с пропусками в обоих ключах могут соединиться.

07Четыре примера на заказах магазина

Запускайте блоки по порядку в одном ноутбуке. В первом блоке оставим 25 оплаченных заказов из 32 и найдём для каждого клиента месяц его первого оплаченного заказа в выгрузке. Дата платежа отдельно не записана, поэтому в этом примере месяц оплаты определяем по дате заказа. Затем посчитаем число клиентов, заказы и выручку каждой когорты.

Во втором блоке построим сводную таблицу выручки по месяцам и каналам и разберём, почему вызов pivot на тех же заказах выдаёт ошибку.

В третьем блоке присоединим к заказам названия стран. Затем добавим в справочник запись с повторяющимся кодом и проверим, как это повлияет на число строк.

В четвёртом блоке переведём сводную таблицу в длинный формат и построим график выручки с отдельной линией для каждого канала.
