Оконные функции

Магазину нужно узнать, через сколько дней покупатели возвращаются за вторым заказом. С помощью оконных функций вы добавите к каждому заказу дату предыдущей покупки, посчитаете выручку нарастающим итогом и разберётесь, когда среднее за семь строк отличается от среднего за семь дней.

01Как получить итог по клиенту и сохранить каждый заказ

Пусть в таблице одна строка соответствует заказу. Если сгруппировать её по клиенту и сложить суммы, в результате будет одна строка на клиента. Оконная функция позволяет оставить каждый заказ отдельной строкой и добавить к нему результат расчёта. После OVER задают правила расчёта. PARTITION BY выделяет секцию, например все заказы одного клиента. ORDER BY задаёт порядок внутри неё. У агрегата рамка определяет, какие строки учитывать для текущего заказа. Так можно получить нарастающий итог от первой покупки клиента до очередного заказа.

Переключайте шаги кнопками под анимацией или клавишами ← и →.

Как задать окно

После имени функции и её аргументов указывают OVER. В скобках можно задать секцию, порядок строк и границы рамки2.

функция(…) OVER (PARTITION BY … ORDER BY … рамка)секция · порядок внутри секции · какие строки секции брать для текущей

Пустые скобки OVER () объединяют в одну секцию все строки, доступные на этом этапе запроса. Например, если WHERE отобрал только оплаченные заказы, в расчёт войдут только они. Если уже была группировка, окно работает по строкам групп. В PostgreSQL 16 оконную функцию можно вызвать в SELECT и ORDER BY. Её значение вычисляется после WHERE, GROUP BY и HAVING, до финальной сортировки и ограничения LIMIT1. Общее для нескольких функций окно удобно определить один раз в WINDOW и затем использовать по имени, например OVER w4.

Ранжирование: ROW_NUMBER, RANK, DENSE_RANK

Разница между тремя функциями заметна, когда несколько заказов имеют одинаковую сумму. Такие строки равны по ключу сортировки в окне3. ROW_NUMBER присваивает каждой строке отдельный номер. Если других ключей сортировки нет, запрос не определяет, какой из двух одинаковых по сумме заказов получит меньший номер. RANK даёт обоим одно место и пропускает следующее. DENSE_RANK присваивает одно место каждой особой сумме, без пропусков. Сравните номера семи самых крупных заказов в учебной выборке.

Как выбрать три самых продаваемых товара в каждой категории? Разбейте товары на секции по категории и отсортируйте по числу проданных штук. Фильтр по ROW_NUMBER оставит до трёх товаров на категорию. Фильтр DENSE_RANK <= 3 сохранит все товары с тремя наибольшими различными значениями продаж. Товаров при этом может оказаться больше трёх.

Как сравнить заказ с предыдущим или следующим

LAG возвращает значение из предыдущей строки той же секции, LEAD — из следующей. Можно указать смещение в строках и результат на случай, если такой строки нет. По умолчанию смещение равно единице, а результат для отсутствующей строки — NULL3. Выручка магазина за январь, февраль и март составила 173 900, 278 950 и 459 230 ₽. Вызов LAG(revenue) OVER (ORDER BY month) добавляет к каждому месяцу выручку предыдущего месяца в этой выборке. В феврале выручка выросла на 60,4%, в марте — на 64,6%. Для января предыдущего значения в выборке нет.

Агрегаты по окну: доля, итог, скользящее среднее

Агрегаты SUM, AVG и COUNT можно использовать с OVER. Тогда в каждой строке будет результат расчёта по её рамке3. Для доли заказа в выручке канала нужна сумма всей секции. Например, выражение 100.0 * amount / SUM(amount) OVER (PARTITION BY channel) даёт долю в процентах. Множитель 100.0 в PostgreSQL позволяет сохранить дробную часть при делении целых сумм. В недельной выборке на заказ № 1153 приходится 83,6% выручки от рассылки.

Чтобы посчитать нарастающий итог по заказам, упорядочьте их по дате и номеру и задайте рамку от начала секции до текущей строки. Для скользящего среднего можно взять более короткую рамку. Например, AVG(revenue) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) усредняет текущую строку и до шести предыдущих. Если за какой-то день записи нет, дата самой ранней строки может оказаться за пределами последней календарной недели.

Последняя запись по ключу

В журнале статусов у заказа бывает несколько записей, для отчёта нужна последняя. Один из способов дедупликации — пронумеровать записи каждого заказа от поздних к ранним и оставить номер 1. В PostgreSQL фильтр по этому номеру помещают во внешний запрос1. Если время двух событий может совпасть, понадобится дополнительное правило выбора, например больший уникальный номер события.

Те же расчёты в pandas

В главе о pandas вы уже добавляли к каждому заказу итог по его группе через transform. Для других оконных расчётов тоже есть похожие операции10. Чтобы результаты совпали, проверьте порядок строк, границы окна и число наблюдений, необходимое для первого результата.

SQLpandas
SUM(amount) OVER (PARTITION BY channel)groupby("channel")["amount"].transform("sum")
SUM(amount) OVER (PARTITION BY customer_id ORDER BY order_date, order_id ROWS UNBOUNDED PRECEDING)groupby("customer_id")["amount"].cumsum() после сортировки по дате и номеру заказа
LAG(order_date) OVER (…)groupby("customer_id")["order_date"].shift()
ROWS BETWEEN 6 PRECEDING AND CURRENT ROWrolling(7, min_periods=1)
RANGE BETWEEN INTERVAL '6 days' PRECEDING AND CURRENT ROWrolling("7D") для дневных итогов с одной строкой на дату
ROW_NUMBER, RANK, DENSE_RANKrank(method=…): "first", "min", "dense"

Перед shift или cumsum в pandas отсортируйте строки внутри группы. В SQL порядок для оконной функции задаётся в OVER. Отдельный ORDER BY в конце запроса определяет, в каком порядке строки увидит читатель.

02Четыре задачи на данных магазина

В учебной базе есть заказы за январь–март 2026 года, состав каждого заказа, каталог товаров и журнал статусов. Эти таблицы уже встречались в уроках 3.1–3.4. Теперь по ним нужно подготовить четыре отчёта.

  • Удержание клиентов. Какую долю покупателей магазин увидел снова и сколько дней прошло между покупками?
  • Выручка за семь календарных дней. Как учесть даты, когда не было продаж?
  • Лидеры продаж. Какие товары заняли первые три места в каждой категории и как учитывать одинаковые результаты?
  • Последний статус. Какая запись журнала соответствует текущему состоянию каждого заказа?

Во всех четырёх задачах расчёт использует несколько строк одной группы. Например, для паузы между заказами нужны две покупки клиента, но результат относится к конкретной покупке. Подобные отчёты разбирают Кэти Танимура6, Энтони Молинаро и Роберт де Грааф7.

03Какие строки входят в рамку

У рамки есть режим и две границы. Например, ROWS BETWEEN 2 PRECEDING AND CURRENT ROW означает «от двух строк перед текущей до текущей включительно». Ключевое слово UNBOUNDED обозначает начало или конец секции, а FOLLOWING — смещение вперёд2.

В режиме ROWS смещение измеряется числом строк. В режиме RANGE границы зависят от значения ключа сортировки. Например, при сортировке дат по возрастанию рамка RANGE BETWEEN INTERVAL '2 days' PRECEDING AND CURRENT ROW включает записи за текущую дату и два предыдущих календарных дня, если такие записи есть. Для RANGE со смещением PostgreSQL 16 требует одно выражение в ORDER BY и совместимый тип смещения. Для даты здесь указывают интервал: INTERVAL '2 days'.

В режиме ROWS граница CURRENT ROW указывает на конкретную строку. В режиме RANGE такая конечная граница включает и все строки с таким же ключом сортировки2. Если указан ORDER BY без явной рамки, по умолчанию действует RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW. Без сортировки и явной рамки агрегат учитывает всю секцию. Функции ROW_NUMBER, RANK, DENSE_RANK, LAG и LEAD используют строки секции независимо от границ рамки3.

В интерактиве 11 оплаченных заказов бренда «Сова» за 1–7 марта. Первого и шестого марта было по три заказа, четвёртого и седьмого — по два, пятого — один. Второго и третьего марта заказов не было. Сначала попробуйте предсказать сумму для первого заказа.

Таблица показывает строки по секциям и ключам из ORDER BY окна. Если ключи совпадают, PostgreSQL не гарантирует порядок внутри такой группы4. Звёздочка у результата означает, что при другом допустимом порядке равных строк число может измениться. В интерактиве можно выбрать строку, увидеть её рамку и сравнить результаты разных функций.

04Что меняется при совпадении дат или рангов

Нарастающий итог за день или после каждого заказа. Выражение SUM(amount) OVER (ORDER BY order_date) даёт один итог для всех заказов с одной датой. У трёх заказов за 1 марта это 4 070 ₽. Для итога после каждого заказа нужно задать порядок и внутри дня. Одной замены RANGE на ROWS для этого недостаточно. В нашем примере порядок однозначно задаёт ORDER BY order_date, order_id. Если оставить в окне только дату, значения при выводе по номеру заказа могут выглядеть так, будто накопленная сумма уменьшается.

Фильтр по результату оконной функции. В PostgreSQL 16 попытка вызвать оконную функцию прямо в WHERE даёт ошибку window functions are not allowed in WHERE1. Чтобы найти заказы дороже среднего по своему каналу, сначала посчитайте среднее в CTE или подзапросе. Затем сравните с ним сумму заказа во внешнем WHERE.

Одинаковое число проданных товаров. Два товара в категории «Посуда» проданы в одинаковом количестве — по 21 штуке — и делят второе место3. Если взять три первых различных значения продаж с помощью DENSE_RANK, в отчёт войдут четыре товара. Если нужны ровно три из этой категории, используйте ROW_NUMBER и укажите правило выбора при равных продажах.

05Когда оконной функции нужна сортировка

Функции, которым важен порядок строк, могут потребовать сортировки. В учебном плане запроса три функции используют два разных окна, и PostgreSQL выбрал два узла Sort и два WindowAgg. Для другой выборки план может быть иным: иногда подходит порядок индекса или результат предыдущей сортировки.

  • Если несколько функций используют одинаковую секцию и порядок, PostgreSQL может переиспользовать сортировку. Имя в WINDOW удобно тем, что определение окна записано один раз.
  • Отбор до оконного расчёта уменьшает число его входных строк. Для скользящего среднего сначала оставьте в выборке и даты, нужные для первого окна. Ограничить даты вывода можно уже во внешнем запросе.
  • Подробнее о том, как читать план запроса и проверять, использован ли индекс, — в главе 3 блока «Дата инженерия».

06От повторных покупок до последнего статуса

Первый пример находит предыдущую дату покупки каждого клиента с помощью LAG. Затем запрос распределяет клиентов по месяцу первой покупки в выборке и считает, сколько из них сделали второй заказ. Условие FILTER ограничивает строки для конкретного агрегата. Например, COUNT(*) FILTER (WHERE n = 2) и COUNT(CASE WHEN n = 2 THEN 1 END) здесь дают одно число5.

Второй пример сравнивает два способа усреднить дневную выручку. За 24 января и за 26–28 января в выборке нет строк. Проследите, как далеко назад от 29 января уходит рамка из семи строк и сколько дат с продажами есть в последних семи календарных днях.

Третий пример ранжирует товары внутри категории по числу проданных штук. Сравните места товаров с одинаковыми продажами и посмотрите, какие из них попадут в первую тройку при каждом правиле.

Четвёртый пример выбирает для каждого заказа последнюю запись журнала и сверяет её с orders.status. Выражение BOOL_OR(status = 'paid') OVER (PARTITION BY order_id) отдельно показывает, была ли оплата хотя бы в одной записи истории этого заказа.

В DuckDB можно отбирать строки по результату оконной функции прямо в QUALIFY9. PostgreSQL 16 эту конструкцию не поддерживает. В следующем примере один и тот же запрос передаётся обеим системам.
