# Задание для Claude Code: «Аналитика 101» на GitHub Pages

Нужно выложить курс «Аналитика 101» на GitHub Pages: создать репозиторий, настроить сборку через GitHub Actions, проверить сайт после публикации. Тексты курса вычитаны и согласованы, поэтому задача — сборка и публикация, а не правка содержания.

## 0. Что уточнить у автора до начала

1. Аккаунт или организация на GitHub и имя репозитория (например, `analytics-101`). Адрес сайта будет `https://<аккаунт>.github.io/<репозиторий>/`.
2. Видимость. На бесплатном плане GitHub Pages публикует только публичные репозитории: исходники страниц, генераторы данных и материалы станут открытыми.
3. Свой домен не настраивать, пока автор не попросит.

## 1. Что есть на входе

Папка проекта на компьютере автора — «Учебник — материалы проекта». Для репозитория из неё нужны две подпапки:

| в папке проекта | в репозитории | что это |
|---|---|---|
| `source/` | корень репозитория | исходники: `build.py`, `engine/`, `pages/`, `data/`, `tools/`, `README.md`, `ENGINE.md`, этот файл, `deploy/pages.yml` (workflow), `.gitignore` |
| `materials/` | `dist/materials/` | собранные материалы: папка и архив на каждую страницу, общие наборы данных, `index.json` |

Папка `output/` — те же страницы, собранные локально, в репозиторий её не класть: CI собирает страницы сам. Папку `notebooklm/` и документы проекта (`00 …md` – `13 …md`, `Вычитка/`) тоже не класть.

Размеры: `pages/` ≈ 8 МБ, `data/` ≈ 56 МБ, `dist/materials/` ≈ 92 МБ, самый большой файл ≈ 15 МБ. Git LFS не нужен: лимит GitHub — 100 МБ на файл, рекомендуемый размер репозитория — до 1 ГБ.

## 2. Как устроена сборка

Всё на Python 3.13 без сторонних библиотек:

```bash
python3 build.py --all            # pages/<id>/ → dist/standalone/<файл>.html, 43 страницы
python3 tools/build_site.py       # site/: index.html, course.html, 404.html, страницы, materials/
python3 tools/check_site.py       # внутренние ссылки, якоря и файлы материалов; код выхода 1 при ошибке
python3 -m http.server -d site 8000
```

- `engine/course.json` — структура курса: модули, темы, страницы, описания тем, лид главной. Из него собираются боковина страниц, главная и оглавление. Файл генерирует `tools/make_course.py` из программ блоков, которые лежат в папке проекта, а не в репозитории. Поэтому `course.json` коммитится, а перегенерировать его нужно только при добавлении страниц: `python3 tools/make_course.py "<папка проекта>"`.
- `engine/notebooks.json` — ссылки на блокноты NotebookLM по темам (`da-01` … `da-11`). Пока `url` пустые, пункт «NotebookLM» в меню «Обсудить с ИИ» серый с пометкой «скоро».
- `dist/materials/index.json` — карта материалов. `build.py` вшивает её в страницы: ссылки «скачать», размеры, архив страницы.
- Все ссылки относительные (`course.html`, `materials/…`), поэтому сайт работает по адресу вида `/<репозиторий>/` без настройки базового пути. Не превращать их в абсолютные от корня (`/course.html`).
- Отметки «пройдено» хранятся в `localStorage` под ключом `a101-done` (массив id страниц), ответы на вопросы — под `<id страницы>-answers`. Хранилище привязано к домену: при переезде на другой адрес прогресс читателей не перенесётся.

## 3. Шаги

1. Собрать рабочую копию по таблице из п. 1 и проверить локально: три команды из п. 2, затем `check_site.py` должен выдать «ошибок 0». Открыть `http://localhost:8000/` и пройти чек-лист из п. 4.
2. Перенести workflow на место: `mkdir -p .github/workflows && mv deploy/pages.yml .github/workflows/ && rmdir deploy`. В папке проекта на компьютере он лежит в `deploy/`: папку `.github` туда записать нельзя.
3. `git init -b main`, первый коммит. Проверить, что `dist/materials/` попал в коммит, а `dist/standalone/`, `dist/artifact/` и `site/` — нет: так настроен `.gitignore`.
4. Создать репозиторий и запушить: `gh repo create <аккаунт>/<репозиторий> --public --source . --push`.
5. Включить Pages с публикацией из Actions: Settings → Pages → Build and deployment → Source: GitHub Actions. То же через API: `gh api -X POST repos/<аккаунт>/<репозиторий>/pages -f build_type=workflow`.
6. Workflow `.github/workflows/pages.yml`: сборка страниц и сайта, проверка ссылок, публикация. Он запускается на каждый push в `main` и вручную (`workflow_dispatch`). Если первый push прошёл до включения Pages, перезапустить: `gh workflow run pages.yml`.
7. Дождаться зелёного запуска (`gh run watch`) и пройти чек-лист п. 4 уже на опубликованном адресе.
8. Отчитаться автору: адрес сайта, ссылка на репозиторий и на успешный запуск, результат чек-листа, всё, что пришлось поменять, — с причинами.

Версии действий в workflow сверены в ноябре 2026: `actions/checkout@v6`, `actions/setup-python@v6`, `actions/configure-pages@v5`, `actions/upload-pages-artifact@v4`, `actions/deploy-pages@v4`. Если у какого-то вышла новая основная версия, обновить можно, но после этого проверить запуск. Права `pages: write` и `id-token: write` нужны для публикации, окружение `github-pages` создаётся само. Файл `.nojekyll` в `site/` нужен только при публикации из ветки: при публикации через Actions Jekyll не запускается.

## 4. Чек-лист приёмки

На ширине 1440 и 360 px, в светлой и тёмной теме системы:

- **Главная** (`index.html`): заголовок «Аналитика 101», лид, пять кнопок модулей. «Дата аналитика» ведёт в `course.html#da`, остальные — в оглавление своего модуля с пометкой «в работе».
- **Оглавление** (`course.html`): переключатели модулей; у «Дата аналитика» 11 карточек тем с описанием, отрывком из первой страницы и списком страниц с чекбоксами. Отметка сохраняется после перезагрузки, счётчики «N из M» у темы и модуля меняются, на главной у кнопки появляется «пройдено N из 43». Ссылка `course.html#da-07` открывает модуль и прокручивает к теме 07, карточка не прячется под шапкой.
- **Страница курса**: «Аналитика 101» в шапке ведёт на главную; в боковине живые ссылки на страницы темы и первые страницы других тем, ✓ у отмеченных; «Оглавление курса →» ведёт к теме в оглавлении. Меню «Обсудить с ИИ»: два пункта «Обсудить», серый «NotebookLM · скоро», ссылки Claude, ChatGPT, Gemini.
- **Материалы**: на 2–3 страницах скачать отдельный файл, архив страницы и архив общего набора (`data-shop.zip` на страницах темы 03). Файлы открываются, размеры совпадают с подписью.
- **404**: несуществующий адрес на верхнем уровне показывает страницу «Такой страницы нет» со ссылками на оглавление и главную. Ссылки в ней относительные, поэтому со вложенного адреса вроде `/materials/нет-такого/` они ведут мимо — это допустимо.
- В консоли браузера нет ошибок; горизонтальной прокрутки на 360 px нет.

Для глубокой проверки одной страницы есть `node tools/qa.js "<абсолютный путь к странице>.html"`: консоль, шаги сцены, интерактивы, вопросы, 360 px. Нужны Node.js и Playwright.

## 5. Когда будут готовы блокноты NotebookLM

Автор пришлёт публичные ссылки на 11 блокнотов. Их нужно вписать в `engine/notebooks.json`, в поле `url` нужной темы, и запушить. CI пересоберёт страницы: пункт «NotebookLM» в меню станет ссылкой на блокнот темы, а в разделе «Материалы» название блокнота станет ссылкой. Ссылку брать ровно ту, что выдаёт кнопка «Поделиться» в NotebookLM. С июля 2026 года Google называет продукт Gemini Notebook и может переадресовывать `notebooklm.google.com` на `notebook.google.com` — подпись кнопки на сайте остаётся «NotebookLM», это решение автора.

## 6. Чего не делать

- Не менять тексты, числа, код и вопросы в `pages/*/article.html` и `pages/*/page.js`: вычитка закрыта. Найденную ошибку записать в отчёт, а не исправлять.
- Не пересобирать материалы (`tools/build_materials.py`, `tools/build_shared_data.py`) и не трогать `dist/materials/`: для этого нужны PostgreSQL 16, Jupyter и данные, а результат сверен с текстами страниц.
- Не добавлять счётчики, аналитику, внешние скрипты и шрифты: страницы грузят только Google Fonts.
- Не включать Jekyll и не менять структуру папок сайта: страницы, главная и оглавление лежат в корне `site/`, материалы — в `site/materials/`.

## 7. Бэклог движка — только по согласованию с автором, отдельными PR

Из «10 Вычитка — Дата аналитика», раздел 4. Каждый пункт решается в `engine/` с последующей пересборкой всех страниц и уборкой обходов из `page.css`:

- табло `.sc-info` наезжает на 3–4 счётчика HUD, его прячут в `page.css` на 29 страницах;
- `.out pre`: `max-height: 320px` прячет хвост вывода, а `pre-wrap` ломает таблицы psql на телефоне, переопределено на 20 страницах;
- `.formula .f` с `nowrap`: длинные формулы на 360 px вылезают за край;
- лигатуры JetBrains Mono (`>=` рисуется как ≥), моноширинный `svg text` во встроенных рисунках, высота сцены и отступ `.sc-html` как параметр страницы;
- верхний регистр в HUD превращает греческие буквы в заглавные (σ → Σ): сейчас вместо букв слова;
- заголовки шагов сцены вставляются как текст, поэтому `&nbsp;` в них показался бы буквально (сейчас таких заголовков нет);
- иконка сайта, Open Graph для превью ссылок, ссылки «предыдущая / следующая» внизу страницы.
